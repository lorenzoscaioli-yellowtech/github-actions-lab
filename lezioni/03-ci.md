# Lezione 03 - Continuous Integration

File: `.github/workflows/03-ci.yml` · App: `app/`

## Cosa dimostra

- Il pattern base di ogni CI: checkout → setup runtime → installa → testa.
- `actions/setup-node` con `cache: npm`: la cache si basa sull'hash del
  lockfile, quindi al secondo run `npm ci` è molto più veloce.
- `npm ci` invece di `npm install`: installa esattamente il lockfile.
- `defaults.run.working-directory` per non ripetere `cd app`.
- `permissions: contents: read`: il token ha solo ciò che serve.
- `actions/upload-artifact`: la build e l'output dei test sopravvivono al
  runner e si scaricano dal run.

## Come lanciarla

```bash
gh workflow run 03-ci.yml && gh run watch
gh run download --name build-e-report -D /tmp/ci   # scarica l'artefatto
```

Oppure toccare qualcosa in `app/` e fare push o aprire una PR.

## Cosa osservare nei log

1. Step setup-node: la prima volta "Cache not found", dalla seconda
   "Cache restored from key: ...".
2. Il riepilogo del run mostra `pass 3 / fail 0`.
3. In fondo alla pagina del run compare l'artefatto `build-e-report`.

## Da provare

- Rompere un test (`assert.equal(somma(2, 3), 6)`) e aprire una PR: il check
  diventa rosso e blocca il merge se il branch è protetto.
